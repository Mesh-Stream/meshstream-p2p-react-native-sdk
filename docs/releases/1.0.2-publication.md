2026-10-29，`react-native-meshstream@1.0.2` 已发布到公共 npm，`latest` 指向 `1.0.2`。示例已恢复为 npm 精确版本，更新了依赖锁文件。发行 Git 分支为 `main`，标签为 `1.0.2`。

```bash
npm install react-native-meshstream@1.0.2
```

## 公网安装后的运行验收

测试平台：PFJM10 / Android 13 / arm64-v8a 真机；iPhone 18 Pro / iOS 27.0 / arm64 模拟器。使用同一条 Mux Big Buck Bunny HLS 和本轮唯一 contentId，确认只有该测试组合加入；两端均观察到视频画面及持续播放进度。未调用 preload，本次不用于比较预热或首帧性能。

确认分享方向为 **iOS 模拟器 → Android 真机**：

| P2P 阶段快照 | Android | iOS |
| --- | --- | --- |
| P2P 下载字节 | 2,181,740 | 0 |
| HTTP 下载字节 | 719,560 | 3,461,960 |
| 成功 P2P 下载片段 | 7 | 0 |
| P2P 上传字节 | 60 | 2,520,796 |
| 成功上传次数 | 0 | 8 |
| 下载分流率 | 75.2% | 0% |
| Peer 数 | 1 | 1 |
| tracker / peer connect 错误 | 0 / 0 | 0 / 0 |

上传与下载是异步采样统计，不能要求字节对称。Android 的 60 字节及零成功上传不能视为反向媒体传输；**Android → iOS 分享尚未验收**。75.2% 是本轮特定样本，不是固定分享率。

随后双端调用 `session.setP2pEnabled(false)`，Peer 均降为 0，P2P 下载字节停止增长，HTTP 下载继续增长：

| 受控 CDN 回退窗口 | Android | iOS |
| --- | --- | --- |
| HTTP 起始字节 | 719,560 | 3,461,960 |
| HTTP 结束字节 | 2,558,996 | 6,836,318 |
| HTTP 增量 | 1,839,436 | 3,374,358 |

两端播放进度继续推进，未出现 `playerError`。这是主动禁用 P2P 的受控回退验证，未模拟对端骤断或网络中断。最终 iOS HTTP 片段失败计数为 2，Android 为 0；P2P 下载失败计数为 iOS 4、Android 2，Android 上传失败计数为 4。已观察到回退后继续播放，不宣称零网络失败或双向上传验收完成。

双端 `session.close()` 与 `client.close()` 完成。另行验证了两客户端、三个会话的隔离：跨客户端伪造会话访问被拒绝；关闭一个会话不影响同客户端兄弟会话和另一客户端；关闭客户端后其会话访问被拒绝，另一客户端继续可用。两端均通过，辅助客户端全部关闭。

临时测试入口、控制服务器及含 Key 的配置已清理，客户示例恢复正常入口；测试凭据及原始遥测不进入公开仓库。
