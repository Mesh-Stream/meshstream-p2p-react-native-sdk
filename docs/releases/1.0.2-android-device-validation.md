## 实测结果

使用用户提供的 Android Key（未写入代码），播放 Mux Big Buck Bunny 单路 HLS，contentId 留空，由 SDK 生成。通过 SDK 返回的本地代理 URL 进行播放；已观察到视频画面，Android 日志显示 H.264/AAC 解码与音频输出正常启动。

| 项目 | 实测 |
| --- | --- |
| 连接 Peer | 1 |
| P2P 下载 | 7.6 MiB，随后继续增长到 10.4 MiB |
| HTTP 下载 | 同期 2.2 MiB，随后增长到 2.9 MiB |
| 下载分流率 | 页面显示 78%（7.6 MiB / 2.2 MiB 样本） |
| P2P 上传 | 该样本为 0 B，上传方向尚未验收 |
| 首个 Peer | 16113 ms；本次未调用 preload，不能当作预热性能结果 |
| P2P 状态 | 已启用 / OK |
| Tracker | 就绪，错误数 0 |
| 地域 / 配额 | as / available |
| 回源次数 | 26（上述诊断样本），不是播放器错误次数 |
| 关闭流程 | 点击关闭后显示“会话与客户端已关闭”，播放及遥测面板移除，日志显示播放器释放 |

页面以 MB 标注的字节值实际按 1024² 换算，以上用 MiB 表示；它们是四舍五入后的页面采样值，并非原始精确字节数。该场景说明真实 P2P 下载已发生，78% 不能视为所有网络环境的固定分享率。未确认对端身份，不能据此宣称某个指定平台组合或反向上传验收完成。

关闭后设备 `ss -ltn` 输出中不再出现该会话代理端口，但设备同时报告 netlink 权限受限，因此该检查仅作为补充。ADB 转发代理请求未获得成功响应，不作为关闭前后的可用性证明。
